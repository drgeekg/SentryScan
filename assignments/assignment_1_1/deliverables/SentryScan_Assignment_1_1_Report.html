1. Executive Summary & Theoretical Context

Assignment 1.1 establishes the foundational theoretical, behavioral, and architectural specifications for SentryScan—an authorized autonomous vulnerability scanner agent simulation designed for synthetic telemetry analysis.

1.1 Problem Statement & Agent Persona

Modern enterprise security teams face severe alert fatigue and the operational hazards of intrusive live vulnerability scanning. SentryScan acts as an Autonomous Defensive Telemetry Analyst: - Defensive Posture: Operates strictly on perceived telemetry rather than active exploitation. - Safety Boundary: Synthetic simulation only. All host addresses strictly use IETF documentation ranges (RFC 5737: 192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24; RFC 3849: 2001:db8::/32). SentryScan never attempts live socket connections to these targets. - Untrusted Telemetry Guarantee: All banners and external strings are treated as untrusted data inputs, precluding injection attacks or arbitrary execution.

1.2 Agent vs. Conventional OOP Paradigm (Russell & Norvig, Ch. 2; Wooldridge)

  • Control Autonomy: SentryScan owns its thread of control. It evaluates resource budgets and operational utility before deciding whether to accept tasks, unlike passive OOP objects which execute methods unconditionally upon invocation.
  • Cognitive Mental State: SentryScan maintains epistemic mental states (Beliefs, Desires, Intentions) rather than raw encapsulated class properties.
  • Speech-Act Communication: Inter-agent interactions use formal performatives (CFP, PROPOSE, ALERT, CONFIRM) rather than rigid remote procedure calls (RPC).

2. Architecture & Implementation Specification

2.1 Formal PEAS Framework

Component Specification for SentryScan
Performance Measure ($P$) - Detection Accuracy: High precision and recall on genuine exposures without false alarms on benign services.
- Data Integrity Defense: Detection rate of poisoned/mutated records without access to ground truth.
- System Stability & Latency: Minimal queue turnaround time; bounded memory footprint; zero dropped events.
- Protocol Compliance: Handshake resolution rate in multi-agent negotiation; bounded rounds ($\le 5$); zero unauthorized message acceptances.
- Audit Completeness: 100% gap-free event sequence persistence (seq).
Environment ($E$) - Simulated Endpoint Fleet: Heterogeneous synthetic hosts (sim-host-001 … sim-host-N) generating concurrent telemetry.
- Telemetry Stream: Ingestion queue carrying normal baseline records, malformed payloads, and deliberately mutated (poisoned) records.
- Communication Channels: Loopback TCP sockets (127.0.0.1) and in-process message queues.
- Knowledge Repositories: Read-only CVE / NVD data interfaces and local offline caches.
Actuators ($A$) - Finding Publisher: Emits structured Finding objects with deterministic severity, evidence links, and confidence scores.
- Event Recorder: Commits append-only chronological AgentEvent entries with monotonic seq to JSONL and SQLite sinks.
- Envelope Dispatcher: Constructs, signs (Ed25519), and transmits inter-agent messages (ALERT, PARAMS_UPDATE, CFP, PROPOSE, ACCEPT).
- BDI Intention Actuator: Modifies active goals, triggering plan revision or resource reallocation.
- Report Actuator: Generates structured JSON/CSV audit reports and Rich console dashboards.
Sensors ($S$) - Telemetry Sensor: Stream receiver that parses and validates raw telemetry into typed TelemetryRecord objects.
- Integrity Sensor: Rule-based parser checking timestamp drift, hash duplication, service-banner mismatch, and prompt injection strings.
- Socket / Network Sensor: TCP frame listener decoding length-prefixed JSON envelopes and validating security credentials.
- Knowledge Sensor: Client querying local CVE cache and external NVD endpoints for vulnerability enrichment.

2.2 Environment Classification (Russell & Norvig 7 Dimensions)

  1. Partially Observable: The agent observes only surface-level telemetry emitted by devices (ports, service names, version banners). It cannot inspect remote kernel memory or filesystems, and ground-truth poisoning labels are hidden in an isolated evaluator sidecar.
  2. Stochastic: While internal agent reasoning is deterministic, the external telemetry stream introduces variable queue latency, concurrent thread interleaving, synthetic network jitter, and probabilistic injection operators.
  3. Sequential: Decisions constrain future states: suspect record flags update device risk baselines, findings alter BDI beliefs, and task awards consume execution budgets.
  4. Dynamic: The environment evolves continuously as background daemons generate telemetry while scanner workers deliberate.
  5. Discrete: Network ports ($1 \dots 65535$), performatives (ALERT, CFP, etc.), severities (LOW to CRITICAL), and event sequences ($seq \in \mathbb{N}$) are discrete.
  6. Multi-Agent: Supervisor, Scout, Triage, and Analyst agents interact with distinct utilities via Contract-Net negotiation.
  7. Known: Environmental laws (schemas, rules, protocols, utility equations) are fully known to the agent design.
